## 1. Executive Summary & Architectural Taxonomy

Notebook 4 explores the transition from static input encoders (BERT-style) to dynamic sequence generation architectures capable of producing open-ended or translated text ($n \to m$ mapping). It contrasts **Encoder-Decoder** models (T5, Flan-T5) against **Decoder-Only** autoregressive models (GPT-2, Phi-1.5) and breaks down the mechanics of causal attention, KV caching, cross-attention, and streaming generation.

### Comparison Matrix of Core Architectures:

| Architecture Type | Canonical Models | Attention Mechanism | Primary Use Cases | Advantages | Limitations |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Encoder-Only** | BERT, RoBERTa | Bidirectional (Full) | Classification, Named Entity Recognition, Extractive QA | Deep contextual understanding; bidirectional context | Cannot natively generate ordered token sequences ($n \to m$). |
| **Decoder-Only** | GPT-2, Phi-1.5, LLaMA | Unidirectional (Causal Masking) | Open-ended text generation, dialogue, in-context learning | Unified pathway; seamless few-shot prompting; parallel training | Prone to run-on generation and hallucinations without prompt constraints. |
| **Encoder-Decoder** | T5, Flan-T5, BART | Bidirectional (Encoder) + Causal & Cross-Attention (Decoder) | Machine translation, abstractive summarization | Isolates conditioning context from target generation; robust against drift | Two separate pathways; higher latency; less flexible for arbitrary in-context learning. |

## 2. Core Concepts & Mathematical Formulations

### 2.1 Autoregressive Generation & Causal Masking
Decoder-only models factor the joint probability of a sequence $x_{1 \dots T}$ autoregressively:

$$P(x_{1 \dots T}) = \prod_{t=1}^{T} P(x_t \mid x_{<t})$$

- **Causal Masking**: Upper-triangular elements of the attention matrix are set to $-\infty$ before softmax, preventing position $t$ from attending to future tokens $s > t$.
- **Training Efficiency**: All token predictions for an entire sequence can be computed in parallel in a single forward pass via teacher forcing.

---

### 2.2 Prefill vs. Decode Stages and KV Caching
Generating tokens sequentially naively recalculates Keys ($K$) and Values ($V$) for all preceding tokens at every step ($O(T^2)$ compute). **KV Caching** optimizes this by caching past projections:

1. **Prefill Stage**:
   - Ingests the entire prompt sequence in parallel.
   - Computes initial hidden states and populates `past_key_values` tensors for all layers.
2. **Decode Stage**:
   - Ingests only the single newest token ($1 \times d$).
   - Appends new Key/Value vectors to `past_key_values` (`use_cache=True`).
   - Computes attention only for the last query ($1 \times T$).

---

### 2.3 Cross-Attention Mechanics in Encoder-Decoders
Cross-attention allows the decoder to condition its generative steps on the full contextual representation generated by the encoder:

$$\text{Cross-Attention}(Q_{\text{dec}}, K_{\text{enc}}, V_{\text{enc}}) = \text{softmax}\left(\frac{Q_{\text{dec}} K_{\text{enc}}^T}{\sqrt{d_k}}\right) V_{\text{enc}}$$

- Encoder outputs sequence $K_{\text{enc}}, V_{\text{enc}} \in \mathbb{R}^{m \times d}$ (length $m$).
- Decoder supplies queries $Q_{\text{dec}} \in \mathbb{R}^{n \times d}$ (current generation length $n$).
- The attention map is $n \times m$, producing an $n \times d$ output representation compatible with the decoder's hidden dimension.

### Part 4.2: GPT-Style Decoder-Only Generation & Forward Pass Deconstruction

#### 1. High-Level Text Generation Pipeline
```python
from transformers import pipeline

generator = pipeline('text-generation', model='gpt2', device='cuda')
generator("Hello world,", max_length=20, num_return_sequences=5)
```
- Produces 5 stochastic completions using top-$k$/top-$p$ temperature sampling up to a max sequence length of 20 tokens.

#### 2. Manual Prefill and Decode with KV Caching
```python
import torch

model_body = generator.model.transformer
model_head = generator.model.lm_head
tknzr_encode = generator.tokenizer.encode
tknzr_decode = generator.tokenizer.decode

def compute_embed(token_id):
    return model_body.wte(torch.tensor(token_id).to('cuda')).view(1, -1, 768)

# PREFILL STAGE: Ingest prompt and populate KV cache
input_str = generator.tokenizer.bos_token + "Hello world"
embed_buffer = compute_embed(tknzr_encode(input_str))
attention_mask = torch.ones(embed_buffer.shape[:2], dtype=torch.long, device='cuda')

prefill_output = model_body(
    inputs_embeds=embed_buffer,
    attention_mask=attention_mask,
    past_key_values=None,
    use_cache=True
)

past_key_values = prefill_output.get("past_key_values")
predicted_embed = prefill_output.get("last_hidden_state")

# DECODE STAGE: Greedily sample token-by-token
for i in range(20):
    predicted_probs = model_head(predicted_embed[:, -1, :])
    predicted_token = torch.argmax(predicted_probs, dim=-1).item()
    print(tknzr_decode(predicted_token), end="")

    # Append to attention mask and reuse cached KV tensors
    attention_mask = torch.cat([attention_mask, torch.ones((1, 1), dtype=torch.long, device='cuda')], dim=1)
    step_embed = compute_embed(predicted_token)
    decode_output = model_body(
        inputs_embeds=step_embed,
        attention_mask=attention_mask,
        past_key_values=past_key_values,
        use_cache=True
    )
    predicted_embed = decode_output.get("last_hidden_state")
    past_key_values = decode_output.get("past_key_values")
```

### Part 4.4: Modular Token Stream Generator

To handle both encoder-decoder (T5) and decoder-only (GPT/Phi) architectures uniformly, the notebook constructs a universal generator:

```python
import torch

def get_token_generator(pipeline, model=None, tokenizer=None, max_tokens=50):
    model = pipeline.model or model
    tknzr = pipeline.tokenizer or tokenizer
    encoder = getattr(model, "encoder", None)
    decoder = getattr(model, "decoder", None) or getattr(model, "transformer", None)
    lm_head = getattr(model, "lm_head", None)
    dev = decoder.device

    def token_generator(encoder_input: str = "", decoder_input: str = "", max_tokens: int = max_tokens):
        encoder_input_idxs = tknzr.encode(encoder_input)[:-1] * bool(encoder_input)
        decoder_input_idxs = tknzr.encode(decoder_input)[:-1] * bool(decoder_input)
        decoder_inputs = {}

        # 1. Condition decoder on encoder hidden states if encoder is present
        if encoder and encoder_input_idxs:
            encoder_inputs = {"input_ids": torch.tensor([encoder_input_idxs], device=dev)}
            encoder_outputs = encoder(**encoder_inputs)
            decoder_inputs["encoder_hidden_states"] = encoder_outputs.last_hidden_state

        # 2. Accumulate decoding starting from pad_token_id until eos_token_id
        buffer_token_idxs = [] if (tknzr.pad_token_id is None) else [tknzr.pad_token_id]
        buffer_token_idxs += decoder_input_idxs
        buffer_token_str = ""
        max_length = len(buffer_token_idxs) + max_tokens

        while len(buffer_token_idxs) < max_length:
            decoder_inputs["input_ids"] = torch.tensor([buffer_token_idxs], device=dev).long()
            decoder_outputs = decoder(**decoder_inputs)
            model_outputs = lm_head(decoder_outputs.last_hidden_state)

            sampled_token_idx = torch.argmax(model_outputs, -1)[0][-1].item()
            if sampled_token_idx == tknzr.eos_token_id:
                break

            buffer_token_idxs.append(sampled_token_idx)
            buffer_token_old = buffer_token_str
            buffer_token_str = tknzr.decode(buffer_token_idxs)
            buffer_token_new = buffer_token_str[len(buffer_token_old):]

            if buffer_token_new:
                yield buffer_token_new

    return token_generator
```

### Part 4.5: Benchmarking Multi-Task Models: Flan-T5 vs. Phi-1.5

A diverse evaluation dataset spanning 6 cognitive domains is used to compare the models:
1. **Machine Translation**: "Translate from English to Spanish"
2. **Commonsense Reasoning**: "Why can't a fish live out of water?"
3. **Creative Story Generation**: "Continue the story with a creative twist"
4. **Mathematical Problem Solving**: "What is the square root of 144?"
5. **Fact-based Question Answering**: "Who was the first person to walk on the moon?"
6. **Conversational Continuation**: Multi-turn dialogue trajectory.

#### 1. Flan-T5 Large (Encoder-Decoder)
```python
from transformers import pipeline

flan_t5_pipe = pipeline("text2text-generation", model="google/flan-t5-large")
streamer = get_token_generator(flan_t5_pipe)
input_raw_str = "translate English to French: Hello World! How's it going?</s>"

for token in streamer(encoder_input=input_raw_str):
    print(token, end="")
```
- **Strengths**: Follows structured prefixes (`"translate English to French:"`, `"summarize:"`) with high adherence.
- **Limitations**: Inflexible when incorporating few-shot in-context exemplars into the encoder input.

#### 2. Microsoft Phi-1.5 (Small Language Model - Decoder-Only)
```python
from transformers import pipeline

decoder_pipe = pipeline("text-generation", model="microsoft/phi-1_5", stop_token="\n", device="cuda")
streamer = get_token_generator(decoder_pipe)

inputs = {"decoder_input": "Answer based on factual knowledge: Who was the first person to walk on the moon?\n\nAnswer: "}
for token in streamer(**inputs):
    print(token, end="")
```
- **Strengths**: Excellent general-purpose flexibility via single-stream prompt engineering and few-shot in-context learning.
- **Limitations**: Tends to generate run-on sentences without explicit stopping tokens (`stop_token="\n"`).

| Dimension | BERT (Notebooks 2-3) | T5 / Flan-T5 (Notebook 4) | GPT-2 / Phi-1.5 (Notebook 4) |
| :--- | :--- | :--- | :--- |
| **Model Type** | Encoder-Only | Encoder-Decoder | Decoder-Only |
| **Attention** | Bidirectional | Bidirectional + Cross + Causal | Causal Unidirectional |
| **Input/Output** | Sequence $\to$ Labels/Latents | Sequence $\to$ Different Sequence | Sequence $\to$ Extended Sequence |
| **KV Caching** | Not Applicable | Decoder only | Essential for fast generation |
| **Prompt Paradigm**| Fine-tuned Classification Heads | Task Prefix Strings | Few-Shot In-Context Prompts |
